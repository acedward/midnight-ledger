# Inherited vectors — provenance

Everything in this directory came from **another implementation**. Nothing here
is generated by this crate, and `gen_vectors` never writes these files: a
regeneration would destroy exactly the property they exist to prove.

`tests/vectors.rs` replays them, i.e. asserts that `zswap-memo-companion`
reproduces every value **byte for byte**. That is cross-implementation equality
evidence (spec FR-012 / SC-006) available before Phase 6 exists.

## What was inherited, and what was deliberately not

| File | Source project | What it pins | Inherited? |
| --- | --- | --- | --- |
| `00001-memo-hash.txt` | 00001 | `MemoHashV1` = 00001's `memo_to_field` | **yes** — same domain, same derivation |
| `00002-packing.txt` | 00002 | the 00001-lineage memo packing into field elements | **yes** — byte-exact copy |
| *(00002's `commitment.txt`)* | 00002 | 00002's context commitment `C` | **NO** — see below |

### Why 00002's commitment vectors were NOT inherited

The plan says to verify the domain string before inheriting. It does not match:

| | 00001 / **00003** | 00002 |
| --- | --- | --- |
| domain separator | `midnight:zswap-memo[v1]` (23 bytes) | `midnight:zswap-memo-attest[v1]` (30 bytes) |
| opening | `transient_hash([dom])` | `transient_hash([dom] ++ fr(SHA-256(offer_bytes)))` |
| binds | the memo only (Q-3) | the memo **and an enclosed offer's bytes** |

00002's commitment therefore carries offer context that 00003 must not have.
Inheriting `commitment.txt` would have leaked that context into the frozen
layer. Only 00002's *packing* — which is the same 00001 packing, independent of
any domain separator or context — was taken.

00001's own published conformance table was used for the hash instead. It is
the strongest available source: same domain, same derivation, and produced by a
completely separate implementation.

## Why the 00001 values must reproduce on this baseline

00001's ledger tree and this project's pinned baseline
(`4823b5351b17cc49e30f19760dbd30a73cf95e22`, tag `ledger-9.1.0.0-rc.3`) are
different releases, so "the same derivation" is only meaningful if the two
primitives it stands on are the same code. They are — byte-identical files, not
merely compatible versions:

| File | SHA-256 in **both** trees |
| --- | --- |
| `transient-crypto/src/hash.rs` (`transient_hash`, `transient_commit`) | `ff825694740495a27bca10eaa82aa84199d8693896a4a131ee29b35f8cbaacf9` |
| `transient-crypto/src/curve.rs` (`Fr`, `from_le_bytes`, `as_le_bytes`) | `cf0eb95b43cbe339a506bb766defb6203736129097655f9da029315b12ee6f1c` |

Verified with `diff` between
`experiments/00001-zswap-authenticated-memos/midnight-ledger` and
`experiments/00003-spend-proof-memo-binding/midnight-ledger-fork`.

So a replay failure would mean **this crate's derivation is wrong**, never that
the vectors are stale. That is the whole point of freezing them.

## Format

Same as the generated vectors: records separated by blank lines, `key: value`
lines, `#` comments, byte strings as single-line lowercase hex, field elements
as the 32-byte little-endian encoding of `Fr`. `00002-packing.txt` retains
00002's own header verbatim (including its regeneration instructions, which
apply to *that* crate, not this one) precisely so the copy stays byte-exact.
